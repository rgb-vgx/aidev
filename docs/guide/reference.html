Reference: the complete lists

This page lists everything exactly. If the getting-started and debugging pages are the story, this is the dictionary. Every command with every flag, every status, every failure kind, every event type, every environment variable with its default, and every MCP tool with its inputs. Values here are taken from the code, not from memory.

The one rule, once more: aidev runs the agent in an isolated git worktree, then runs the task's own verification commands itself, and only those commands can move a task to SUCCEEDED. The agent saying the work is done changes nothing. The status and failure-kind tables below are shaped by that rule.

CLI commands

Every command takes its flags with two dashes, like --json. Every command that prints something accepts --json for machine-readable output; human-readable text is the default. A task identifier, written <task> below, is either the reference (TASK-000001, case-insensitive) or the UUID. Logs always go to stderr, so piping --json output to jq always works.

aidev task create

Creates a task. Does not run it. At least one --verify is required.

FlagWhat it does
--title T (required)One short line stating what to do. Must be non-blank and at most 200 characters.
--verify CMD (required, repeatable)One command aidev will run itself to verify the task. Repeat for more than one. Commands run without a shell: pipes, redirects, and operators like |, >, and && are rejected at parse time with an explanation.
--repo PATHPath to the git repository. Default: the current directory. An unknown repository is registered as a project automatically.
--description DThe full instruction for the agent.
--acceptance AWhat done looks like, in prose.
--agent NAMEAgent to use. Default: the OPENCODE_AGENT setting, which is build. aidev validates the name itself because OpenCode silently falls back to its default on an unknown name and still exits zero.
--priority NHigher runs first. Default 0. Range -1000 to 1000.
--max-retries NRecorded for a future retry feature. The current version never retries.
--requires-approvalGate the task behind a human decision. It will wait in WAITING_APPROVAL until approved.
--base-ref REFGit ref to branch from. Default: the project's default branch. Checked now rather than at worktree creation.
--timeout DURATIONBound this task's agent run, for example 60m. Default: DEFAULT_TASK_TIMEOUT.
--jsonPrint the created task as JSON.

CommandFlagsWhat it does
aidev task list--status S,S: comma-separated statuses to include; --repo PATH: only tasks for this repository; --limit N: maximum tasks to return; --jsonLists tasks, newest first. An unknown status is rejected and named. A repository with no tasks is an empty result, not an error.

Exits non-zero when the task does not succeed. An approval gate is not a failure: it reports that a human must decide and exits zero.

Task statuses

The authoritative list lives in internal/task/status.go. The SQL CHECK constraint mirrors it, and a test fails if the two drift apart. Adding a status means updating both the Go enumeration and the SQL constraint in a new migration, never editing an applied migration.

StatusWhat it meansWhat can follow it
PENDINGThe task exists but is not yet eligible to run. In the current version nothing blocks a task, so it becomes ready as soon as a run is requested.READY, WAITING_APPROVAL, CANCELLED
READYThe task is eligible to be picked up.RUNNING, WAITING_APPROVAL, CANCELLED
RUNNINGAn agent is executing inside the task's worktree.VERIFYING, FAILED, CANCELLED
VERIFYINGThe agent finished and aidev is independently running the task's verification commands.SUCCEEDED, FAILED, CANCELLED
SUCCEEDEDVerification passed. Terminal: nothing follows. Reachable only from VERIFYING, which is what makes an agent's claim irrelevant.nothing: terminal
FAILEDThe attempt failed: the agent errored, timed out, or verification did not pass. Terminal.nothing: terminal
CANCELLEDA human or a shutdown stopped the task. Terminal.nothing: terminal
WAITING_APPROVALThe task is gated by policy and will not execute until an approval is granted. No worktree and no attempt exist yet.READY (granted), FAILED (denied), CANCELLED

Two properties are asserted by tests rather than left to review. First, VERIFYING is the only state that can reach SUCCEEDED: there is no edge from RUNNING to SUCCEEDED. Second, every non-terminal state can reach CANCELLED, so no task is unstoppable. FAILED to READY (retry) is deliberately absent: attempts are numbered and appended so retry can be added later, but the edge does not exist yet.

Failure kinds

task.FailureKind is the shared vocabulary for why something failed. The values come from failure modes actually provoked during research, not from imagination. An unclassifiable failure is recorded as UNKNOWN rather than forced into a plausible bucket.

KindCause
STARTUPThe agent process could not start or rejected its arguments. Observed example: an invalid working directory exits 1 with a message on stderr and nothing on stdout.
AGENT_ERRORThe agent reported an error in its own event stream. Observed example: an invalid model produces an error event on stdout.
AGENT_EXITNon-zero exit with no error event.
TIMEOUTaidev's deadline elapsed. Every external process gets a timeout with no exceptions, including verification commands.
CANCELLEDA human or a shutdown stopped it.
VERIFICATIONThe agent finished but verification did not pass. This is the expected failure mode, not an anomaly: it is the one rule producing a FAILED task.
WORKTREEThe isolated workspace could not be prepared or inspected.
APPROVAL_DENIEDPolicy refused: a human denied the approval request.
INTERNALaidev itself failed, for example a database error.
UNKNOWNUnclassifiable. Kept as an honest bucket rather than a plausible guess.

Classification never trusts the exit code alone. An unknown agent name makes OpenCode print a warning, fall back to its default, and exit zero, so aidev validates agent names itself. See the task result section for how to read a failure kind next to its evidence.

Event types

The event log is append-only. The database rejects UPDATE on the events table with a trigger; the way to correct the record is to append a corrective event. Deleting a task cascades to its history, which is legitimate retention. Payloads are always JSON objects, never bare values, so consumers can always index by field name. Defined in internal/event/event.go; every value below is exact.

Event typeWhen it is appended
task.createdA task was created, in the same transaction as the task row.
task.readyThe task became eligible to run.
task.startedThe task was claimed and its attempt opened, atomically: a task can never be RUNNING without a record of which attempt is running it.
task.succeededVerification passed and the task reached SUCCEEDED.
task.failedThe attempt failed, with the failure kind in the payload.
task.cancelledA human or a shutdown cancelled the task, with the reason in the payload.
task.worktree_createdThe isolated worktree was created for the attempt.
task.worktree_removedThe worktree was removed, on success or by an operator with aidev worktree remove.
task.worktree_retainedThe worktree was kept for inspection after failure or cancellation.
task.worker_startedThe agent subprocess started in the worktree.
task.worker_completedThe agent subprocess finished, with its exit classification in the payload.
task.verification_startedaidev began running the task's verification commands.
task.verification_step_completedOne verification step finished, with its command and exit code.
task.verification_completedThe verification pass finished, with the count of passed steps.
task.approval_requiredThe task was gated behind a human decision.
task.approval_grantedA human approved the task; it becomes READY.
task.approval_deniedA human denied the task; it becomes FAILED with kind APPROVAL_DENIED.

Environment variables

Configuration is read only by internal/config. Nothing else in aidev reads the environment directly. These values may come from the configuration file as well as the environment: aidev reads $XDG_CONFIG_HOME/aidev/config.env, or ~/.config/aidev/config.env when XDG_CONFIG_HOME is unset, unless AIDEV_CONFIG names a different file. Anything exported in the shell overrides the file. Everything is validated at startup and every problem is reported at once. DATABASE_URL is the only required variable; everything else has a default.

VariableDefaultPurpose
DATABASE_URLnone: requiredPostgreSQL connection string, for example postgres://aidev:aidev@127.0.0.1:5434/aidev?sslmode=disable.
WORKSPACE_ROOT$XDG_DATA_HOME/aidev/worktrees, else ~/.local/share/aidev/worktreesWhere task worktrees are created. Every worktree path must resolve inside it.
DEFAULT_TASK_TIMEOUT30mBounds one agent run when the task does not set its own timeout. Deliberately generous: first runs against unseen repositories were measured taking minutes.
DEFAULT_VERIFICATION_TIMEOUT10mBounds one verification step.
OPENCODE_COMMANDopencodeThe OpenCode executable aidev invokes.
OPENCODE_MODELopencode/muse-spark-1.3-contributor-freeModel passed as -m. Needs no credentials. Set to an empty string to let OpenCode choose.
OPENCODE_AGENTbuildDefault OpenCode agent for tasks that do not name one.
MAX_OUTPUT_BYTES1048576 (1 MiB) per captured streamCaps each captured stream before it reaches the database. Output beyond it is dropped and flagged as truncated. Minimum 1024.
WORKTREE_CLEANUPon-successon-success commits the work and removes the worktree; never keeps every worktree. Neither discards failed work.
LOG_LEVELinfoMinimum log level: debug, info, warn, error.
OTEL_EXPORTER_OTLP_ENDPOINTunset: tracing offBase OTLP HTTP URL. Traces post to <base>/v1/traces. Tracing is off unless an endpoint is set.

OTEL_TRACES_SAMPLER_ARG1Sample ratio from 0 to 1. Values outside that range fail at startup.
AIDEV_CONFIG$XDG_CONFIG_HOME/aidev/config.env, else ~/.config/aidev/config.envNames a different configuration file instead of the default. The file is parsed, never executed: values are literal.

Related variables that are not aidev configuration but appear in its workflow: AIDEV_DB_PORT overrides the host PostgreSQL port for make db-up; TEST_DATABASE_URL points integration tests at a database (without it they skip themselves); AIDEV_TEST_OTLP gates the live tracing export test. See the tracing section for the OTLP variables in use.

MCP tools

aidev exposes eight tools to an MCP client such as Claude Code, over stdio. The planner on the other side never learns the OpenCode command line. Shapes are defined once in internal/view and shared by the CLI's JSON output and the MCP schemas, so the two cannot drift apart. What is deliberately not exposed: nothing that runs an arbitrary command, no worktree manipulation, no merge or push, no configuration surface, and no project or event writes.

ToolRequired inputsOptional inputsWhat it does
aidev_create_taskrepo_path (absolute path), title, verification (string array, must be non-empty)description, acceptance_criteria, agent (default build), priority (default 0), requires_approval, base_ref, timeout_secondsCreates a task. Does not run it. Registers the repository as a project if unknown. Appends task.created, all in one transaction.
aidev_run_tasktask (reference or UUID)wait_seconds (default 120, maximum 900, 0 returns at once)Isolates, delegates, verifies, records. May return before the task finishes, with still_running: true; the run continues regardless. Calling it again while a run is in flight joins that run. Read succeeded, which is true only when verification passed.
aidev_get_task_resulttaskinclude_logs (also return the agent transcript, the diff, and full verification output)The outcome of the latest attempt: task, attempt, worker (including the agent's claim as summary), verification evidence, worktree, approval. A failing step's output is included even without logs, trimmed to the last 2000 bytes. Absent sections are omitted rather than empty.
aidev_get_task_eventstaskafter_seq, limit (default 200, maximum 1000)History in order: seq, type, created_at, attempt_id, payload. Returns count and last_seq; pass last_seq back as after_seq to continue.
aidev_list_tasksnonerepo_path, statuses (any of the eight statuses), limit (default 50, maximum 500)Finds work, newest first, with count.
aidev_get_tasktasknoneReturns one task. References are case-insensitive.
aidev_cancel_tasktaskreasonStops a task; its worktree is kept. Errors when the task already finished.
aidev_approve_tasktask, approve (boolean: true grants, false denies)decided_by, reasonA human releases a gated task. Granted moves it to READY; denied fails it with task.approval_denied. Required rather than defaulted, so approval cannot happen by omission.

A run takes as long as the agent does, measured between 9 and 656 seconds, while a client will not wait indefinitely. That is why aidev_run_task waits a bounded time and then returns with still_running set while the task continues. The planner polls aidev_get_task_result. The field to read is succeeded, which is true only when aidev's own verification passed.
